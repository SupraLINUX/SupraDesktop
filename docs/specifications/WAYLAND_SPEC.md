Separar permisos de protocolos privilegiados del cliente estándar. No permitir lectura de otras ventanas ni entrada emulada arbitraria. ## Backend-independent window model (experimental)
[SupraWindow](../../crates/supra-window/src/lib.rs) models toplevel lifecycle before selecting the external compositor backend. Internal tokens are not Wayland serials; the experimental model retains outstanding requests in order. Acknowledgement consumes the matching request and older requests, and the latest acknowledgement before commit supersedes earlier acknowledgements. Actual buffer dimensions may differ from a suggestion. Trusted activation is separate from client requests; no authorization or wire implementation is provided. Close is advisory and preserves mapping, pending configurations and focus; unmap resets configure state and clears focus if applicable. Window identity, seat/client isolation, buffer release, wire serial mapping and queue backpressure, input serial validation and protocol conformance belong to the future backend. Tests cover invalid/stale state, focus, close/remap and destruction; CI pending. No external dependency adopted.

## Configure ordering and advisory close correction
Source: [xdg-shell protocol](https://wayland.app/protocols/xdg-shell), xdg_surface.ack_configure and xdg_toplevel.configure/close. A client may acknowledge an earlier outstanding configure even when a newer one exists, acknowledge multiple before committing, choose dimensions when a hint is zero and continue drawing after an advisory close. The original model incorrectly rejected these cases. The backend-independent queue now retains sent tokens, consumes through an acknowledged token and rejects stale/foreign tokens. Maximum 256 outstanding requests per window is an experimental backpressure policy; the future backend must reserve capacity before emitting a configure, never silently discard a sent serial. Zero suggested dimensions are accepted while committed size remains positive within the existing lab ceiling. Close does not revoke focus or invalidate pending state. No wire implementation, actual buffer lifecycle or security conformance claimed; CI pending. No external source/dependency incorporated.

## Connection-scoped toplevel dispatch
Original [clients module](../../crates/supra-window/src/clients.rs) maps backend-established connection identity and local object IDs to never-reused internal window IDs. The Windows model remains the canonical owner of mapping, focus and stacking; no mutable raw state is exposed through the dispatch wrapper. Client-originated acknowledgements, commits, unmap and destroy resolve within their own connection. Trusted compositor policy methods remain separate. Disconnect removes only the connection's windows, including unmapped pending windows, and returns IDs for backend cleanup; surviving clients remain usable. Tests cover overlapping local IDs, stale/foreign configure tokens, disconnect and identity reuse. ClientId is internal, not a credential or wire identity. The future adapter must bind it to the authenticated transport callback, handle protocol errors and release buffers/render resources; this is not a security boundary or Wayland implementation. CI pending.

## Wire serial adapter contract
Source: https://wayland.app/protocols/xdg-shell (xdg_surface.configure and ack_configure); https://wayland.freedesktop.org/docs/html/apc.html (uint32 display serial API). Original [wire module](../../crates/supra-window/src/wire.rs) owns Connections and translates backend-supplied u32 serials to internal nonwrapping u64 tokens. The pending queue follows send order, not numeric serial order, including u32::MAX→0. Reserve before sending; duplicate outstanding serial on same surface or backpressure rejects without insertion. Ack consumes through the matching serial only after canonical state accepts it; unknown, duplicate/consumed and foreign-surface serials reject. Clear mapping on unmap/destroy/disconnect; surviving connections unaffected. The backend must maintain transport identity and handle failed emission by removing the affected surface, and must own serial generation. A previously consumed serial reused after a full wrap is inherently indistinguishable from the new outstanding serial on the same wire object; no unbounded history or impossible replay-proof claim. No seat/input authorization, buffer ownership or real protocol implementation. Four regression tests; CI pending; no external dependency.

## Buffer ownership and retirement contract
Source: https://wayland.freedesktop.org/docs/html/apa.html and https://wayland.app/protocols/wayland (wl_buffer.release, destroy, wl_surface.attach/commit). Original buffers module tracks connection-scoped objects, nonrecycled internal buffer/use IDs, actual committed uses and trusted renderer completion. A release disposition is generated only when all tracked uses are complete; frame callback timing is not a storage lifetime signal. Destroy/disconnect suppresses release to dead resources and defers retirement until the last use completes. A reused object number cannot receive an old buffer's completion. Pending attach must not call begin_use; replacing an uncommitted attach does not generate release. The adapter must coordinate connection registration, actual imports, validated commits, surface state, event emission and GPU fences; no physical storage is owned here. Cross-surface reuse of the same wl_buffer has undefined core release delivery per protocol; this ledger's conservative last-use rule is not a promise of per-commit wire release. Explicit synchronization and per-commit release require separate adapters. Three regression tests; no external code or dependencies. CI pending.

## Double-buffered surface state
The original [surface module](../../crates/supra-window/src/surface.rs) implements a pure pending/current state contract for wl_surface attach, integer scale, transform and frame callback requests; see https://wayland.app/protocols/wayland (wl_surface). Replacing an uncommitted attachment does not imply buffer use, null attachment is distinct from no change, state persists unless changed, and commit returns old/new state plus ordered pending callback identities. Preview allows the backend to validate before commit. Callback IDs are backend-internal, bounded pending queue 256 (local policy), not a wire resource manager; no frame callback or buffer release is emitted by this module. Discard returns only uncommitted callbacks for cleanup. The future backend must validate dimensions, scale/transform/viewport, role mapping and resource lifetimes atomically with actual buffer ledger/import; committed callback scheduling, damage/regions, synchronized subsurfaces, fractional scale, explicit sync and rendering remain separate. No Wayland conformance or GPU claim. Four regression tests, no dependency adoption; CI pending.

## Serialized logical commit coordination (experimental)
The surface module passed [Rust CI 46046855048](https://github.com/SupraLINUX/SupraDesktop/actions/runs/46046855048). The original [coordinator](../../crates/supra-window/src/commit.rs) binds a single surface to each canonical dispatch WindowId and owns the logical buffer ledger. It preflights role/ack, actual-size presence and bounds, surface generation, and stable buffer ownership/liveness before applying changes under an exclusive mutable borrow. A rejected logical commit preserves pending attachment, callbacks, configure acknowledgement and current state. New attachments create one use token; unchanged and null attachments do not create new uses. Explicit null on a mapped window unmaps and clears configure serials; a bufferless initial commit does not consume the role acknowledgement. Disconnect removes surfaces, returns pending callback IDs and retires buffers without releasing dead resources. The backend still owns protocol object namespace, callback scheduling/unique IDs, imports, logical size/scale validation and physical backing retention. The ledger models one submitted use, not retained drawable pixels after release; unchanged content requires a backend-owned copy or retained backing. No protocol/GPU conformance claimed. Three integrated tests; validation pending.

## Frame callback scheduling (experimental)
Logical commit coordination passed [46050425920](https://github.com/SupraLINUX/SupraDesktop/actions/runs/46050425920), including its three integration tests, Clippy and deterministic fixtures. The original internal frames scheduler now indexes live callback identities and retains committed requests in per-window FIFO order, separate from buffer completion. A trusted backend supplies a visible frame boundary for an actual processed generation; hidden/unmapped surfaces defer, future/zero generations reject, and stale generations from a previous mapping epoch cannot signal after remap. The backend still owns timing policy, real visibility, globally nonreused internal callback identities, resource retirement, and event transport. Pending and committed callbacks are canceled on destroy/disconnect; this is not a wire-level done event. Experimental caps: 512 outstanding per surface, 16384 global, plus existing 256 pending per surface. No silent dropping. See [Wayland core protocol](https://wayland.freedesktop.org/docs/html/apa.html). Four integrated regressions; validation pending. No physical presentation or memory-release claim.

## CPU copy integration boundary
Scheduler correction passed [46052655793](https://github.com/SupraLINUX/SupraDesktop/actions/runs/46052655793). CpuCoordinator exclusively owns the logical Coordinator and retained pixel content, validates copy/geometry before logical commit, releases the just-created client storage use after copying, and preserves copied content on unchanged commits and snapshots on detach/disconnect. A failed import/role/budget check publishes no state. Explicit per-instance pixel budget includes retained renderer snapshots and simultaneous new/old copies; reject rather than overcommit, no performance claim. Internal CPU reference only, not a wl_shm implementation, xdg window geometry, fractional scale or viewport. Four tests, CI pending.

## Independent transform/scale oracle (CI pending)
[Wayland core XML](https://cgit.freedesktop.org/wayland/wayland/tree/protocol/wayland.xml) and [core specification](https://wayland.freedesktop.org/docs/html/apa.html): buffer transform is client-applied, compositor uses its inverse, flipped variants flip around vertical axis before counter-clockwise rotation. New renderer integration test constructs the client buffer by independent row operations from a non-square labelled image, expands cells at integer scales 1/2/3, includes nonzero offset and padding, and verifies all eight transform round trips through actual CPU import, logical size and composition. Explicit rotation direction checks avoid a self-confirming inverse. No wire transport, fractional scale, viewport, output transform or GPU conformance claim. Existing implementation unchanged pending test result.

## Transform oracle verified; single-output CPU frame boundary (CI pending)
[46095345082](https://github.com/SupraLINUX/SupraDesktop/actions/runs/46095345082) PASS: all 24 scale/transform combinations and explicit client rotation direction. The [core protocol](https://wayland.freedesktop.org/docs/html/apa.html) distinguishes frame throttling from storage release; [presentation-time](https://wayland.app/protocols/presentation-time) separately reports actual presentation/discard. CPU adapter acquires canonical snapshots from a bound coordinator, validates geometry/scene before submission, keeps one in-flight frame with opaque token, and captures eligible intersecting generations. Completion is an explicit trusted backend boundary, not a physical presentation timestamp. Discard never drains callbacks. Batch completion preflights generations and duplicate IDs, skips destroyed/unmapped windows, and delegates to existing scheduler for epoch/FIFO semantics. Coordinator and submission identities cannot alias across instances even when numeric IDs repeat. Tests cover stable pixels while newer commits occur, stale/foreign tokens, remap, destroy, discarded/occluded/offscreen and zero-work resubmission. Eligibility for occlusion is supplied by trusted compositor policy; no automatic occlusion, actual output event loop, multi-output scheduling, Wayland wire delivery, wp_presentation or GPU implementation yet.

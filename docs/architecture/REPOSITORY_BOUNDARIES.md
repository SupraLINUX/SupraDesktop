# Fronteras de repositorios y releases
Estado ACCEPTED para nombres, repositorios e independencia, ratificado por mantenedor. Detalles de integración PROPOSED; no implementación. 
- [SupraDesktop](https://github.com/SupraLINUX/SupraDesktop): compositor, glass, UI, apps, shell, acciones/AI Ready, tokens, SDK, protocolos, laboratorios, pruebas y empaquetado portable del escritorio.
- [SupraLINUX](https://github.com/SupraLINUX/SupraLINUX): distribución Arch atómica, snapshot locks, PKGBUILD de integración, SupraDeploy/SupraLayers, adaptador Arkdep y parches, ISO, Calamares, recovery, claves públicas, manifests, VM/hardware y pipeline de releases. Nunca claves privadas en Git.
## Contratos
La distro consume commit/tag/artefacto identificado del escritorio y sus tokens, SDK y esquemas publicados; no duplicar código ni usar ramas flotantes en builds de release. Escritorio consume APIs Linux y contratos de proveedores; puede ejecutarse en otros Linux, sin dependencia runtime de SupraDeploy. Adaptador de actualización opcional, negociado por versión/capabilities. Principios y política upstream canónicos en SupraDesktop. CI escritorio independiente; CI distro prueba integración de versión fijada. Cambios de contrato requieren compatibilidad y pruebas cruzadas. Firma de releases no eleva permisos CI escritorio.
